# Finding を手動で追加する (Add Finding Manually)

## 目的・概要

投資家が、自動収集（Source）経由ではなく、自ら見つけた情報を `Finding` としてシステムに保存する。決算短信PDFのURLを保存したり、気づいたことをテキストメモとして直接書き込んだり、株価・バリュエーションのスナップショットを数値として記録したりする。

Finding は **スナップショット**（その時点で捉えた1個の対象）である。入力された URL が **「流れ」**（再取得すると新着が生まれる適時開示フィード・市場データAPI等）の場合は、Finding ではなく [Source](../../../data/source.md) としての登録がふさわしい。判定は [Sourceか Findingかの判定](../../../data/source.md#source-か-finding-かの判定) のリトマス試験に従う。

## 事前条件

- なし

## 事後条件

- 新しい `Finding` がシステムに保存されること
- 保存された Finding ファイルのフロントマター外側に、情報源の内容を整理した Markdown 本文が記載されていること（`memo` の場合は入力本文がそのまま記載される）
- その Finding に少なくとも1つの [Thought](../../../data/thought.md) が付与されていること（その事実が何に関係し、どう役立つかを記録するため）

## 基本フロー（正常系）

1. 投資家は、追加する Finding の種別（`type`）を選択する。
2. 投資家は、種別に応じたコンテンツ（URL、テキスト本文、または数値データ）を入力する。
3. 投資家は、出所区分（`evidenceTier`）を選択する（適時開示・決算短信なら `primary_disclosure`、IR資料・広報発表なら `company_issued`、業界紙・アナリストレポートなら `third_party`、推測・憶測なら `inference`）。
4. システムは、入力内容を検証する（[Finding の不変条件](../../../data/finding.md#不変条件ビジネスルール)に従い、`type` に応じた必須項目が空でないか、`evidenceTier` が選択されているか）。
5. システムは、入力された情報をもとに `Finding` エンティティを作成する。Finding は中立な事実のスナップショットであり、Company / Sector / Theme への関連は持たない。
6. システムは、Finding ファイルのフロントマター外側に **情報源の内容を整理した Markdown 本文** を生成・記載する（[保存フォーマット（大方針）](../../../data/finding.md#保存フォーマット大方針)に従う）。
7. システムは、その Finding に **少なくとも1つの Thought を付与するよう投資家に促す**（[Add Thought](../add_thought/usecase.md)）。多くの場合は、どの Company / Sector / Theme に関係し、ドライバーツリーのどのノードを埋めるかを示す Thought となる。
8. システムは、作成完了を投資家に通知し、Finding の詳細画面へ遷移させる。

## 代替フロー・例外フロー

- **1a. 入力された URL が「流れ」（適時開示フィード・市場データAPI等、再取得で新着が生まれる取得元）の場合:**
  システムは Finding としての保存ではなく、[Source](../../../data/source.md) としての登録（[Register Source](../register_source/usecase.md)）を提案する。
- **3a. `evidenceTier` が未選択の場合:**
  システムは登録を進めず、選択を必須として求める（企業発信の情報が無自覚に中立な事実として扱われることを防ぐため）。
- **4a. `type` に応じた必須項目が空の場合（`url` / `body` 等）:**
  システムはエラーを返し、入力を促す。
- **6a. ページ内容の取得・本文化に失敗した場合（取得拒否・パース失敗・PDF読み取り不可など）:**
  Markdown 本文として「取得に失敗した旨」「現時点で判明している情報（タイトル・URL・抜粋など）」のみを記載する。本文ゼロでファイルを残さない。
