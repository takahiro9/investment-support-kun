# 情報源を登録する (Register Source)

## 目的・概要

投資家が、継続的に監視したい情報源（企業のIR RSS、適時開示フィード、業界紙、市場データAPIなど）をシステムに登録する。これにより、情報収集パイプラインの対象範囲が明示的に決定される。

登録対象は **「流れ」**（再取得すると新着項目の一覧が生まれうる取得元）でなければならない。単発・静的なコンテンツ（1本の決算説明資料PDF、1本のニュース記事など）は Source ではなく [Finding](../../../data/finding.md) として扱う。判定は [Sourceか Findingかの判定](../../../data/source.md#source-か-finding-かの判定) のリトマス試験に従う。

## 事前条件

- `layer` が `company` または `market` の場合、対象となる `Company` が存在すること
- `layer` が `sector` の場合、対象となる `Sector` が存在すること
- `layer` が `theme` の場合、対象となる `Theme` が存在すること

## 事後条件

- 新しい `Source` が `active` 状態でシステムに保存されること

## 基本フロー（正常系）

1. 投資家は、情報源の種別（`type`）、スコープ層（`layer`）、`layer` に応じた参照先（`companyId` / `sectorId` / `themeId`）、URL、表示名、任意でメモ（`description`）を入力し、登録をリクエストする。
2. システムは、入力された URL が Source（流れ）としてふさわしいか（再取得で新着が生まれうるか）をリトマス試験で判定する。
3. システムは、`layer` に応じて必須となる参照先が入力されていることを検証する。
4. システムは、入力された URL がシステム全体で未登録であることを検証する。
5. システムは、入力された URL への疎通確認（アクセス可能か、指定された種別として正しい応答が返るか）を行う。
6. システムは、新しい `Source` エンティティを `active` 状態で作成し、保存する。
7. システムは、登録完了を投資家に通知し、登録された Source の詳細画面（または一覧画面）へ遷移させる。

## 代替フロー・例外フロー

- **2a. URL が Source（流れ）としてふさわしくない（再取得しても新着が生まれない単発・静的ページ）場合:**
  システムは Source としての登録を行わず、[Finding](../../../data/finding.md) としての追加（[Add Finding Manually](../add_finding_manually/usecase.md)）を提案する。
- **3a. `layer` に応じた参照先が未入力、または対象が存在しない場合:**
  システムはエラーメッセージを返し、入力を促す。
- **4a. URLが既に登録済みの場合:**
  システムはエラーメッセージ（「この情報源は既に登録されています」）を返し、処理を中断する。
- **5a. 情報源へアクセスできない（404エラー、タイムアウト等）場合:**
  システムは警告を表示する。投資家は入力内容を修正するか、警告を無視して登録を強行するかを選択できる。
