# 情報源から Finding を自動取得する (Fetch Findings from Sources)

## 目的・概要

システムが定期的にアクティブな `Source` を巡回し、新しいコンテンツ（適時開示、業界ニュース、市場データ等）を取得して `Finding` として蓄積する。投資家が自ら探しに行かなくても、登録した情報源から自動的に情報が集まる仕組みを実現する。

## 事前条件

- システムに `status` が `active` な `Source` が1件以上存在すること

## 事後条件

- 新規取得されたコンテンツが `Finding` として保存されること
- 保存された Finding ファイルのフロントマター外側に、情報源の内容を整理した Markdown 本文が記載されていること（[保存フォーマット（大方針）](../../data/finding.md#保存フォーマット大方針)）
- 既存 `Finding` のコンテンツが情報源で更新されていた場合（`contentUpdatedAt` が新しい場合）、タイトルおよびソース URL が上書き更新されること
- 対象 `Source` の `lastFetchedAt` が処理実行日時に更新されること

## 基本フロー（正常系）

1. システムは、一定間隔（例: 1時間おき、またはジョブキューのスケジュール）で取得処理をトリガーする。
2. システムは、`status` が `active` な `Source` 一覧を取得する。
3. システムは、各 `Source` に対して以下の処理を繰り返す：
   1. Source の種別（適時開示フィード、市場データAPI等）に応じた適正なパーサー/APIを用いて、最新のコンテンツ一覧を取得する。
   2. 取得した各コンテンツについて、その URL が既に Finding として登録されていないか検証する（重複チェックは `url` をキーにシステム全体で行う。Finding は取得元 Source への関連を持たないため、Source 単位ではなくグローバルに判定する）。
   3. 未登録の新規コンテンツを `Finding` エンティティとしてマッピングする（タイトル、URL、`contentUpdatedAt`、取得日時などを設定）。`evidenceTier` は Source の `layer` と種別から機械的に決定する（例: `layer=company` かつ `type=disclosure_feed` → `primary_disclosure`、`layer=sector` の業界紙 → `third_party`）。Finding は中立な事実のスナップショットであり、Company / Sector / Theme への関連は持たない（出所は `url` / `sourceUrl` に記録）。意味づけ（Thought）は付与せず、未整理の raw 状態で保存する。
   4. 取得元コンテンツの本文（開示資料本文・記事本体等）を読み取り、フロントマター外側に置く **情報源の内容を整理した Markdown 本文** を生成する。本文化に失敗した場合は、判明している情報のみを記載した最小限の本文をフォールバックとして残す。
   5. 新規 Finding をデータベースに保存する（フロントマター + 本文の両方）。
   6. 登録済みの既存 Finding については、情報源から取得した `contentUpdatedAt`（適時開示の公表日時等）を保存済みの値と比較する。取得値が新しければ、タイトル・ソース URL・`contentUpdatedAt` を上書き更新する（本文の再生成は任意）。
   7. Source の `lastFetchedAt` を現在の時刻に更新して保存する。

## 代替フロー・例外フロー

- **3-1a. Source へのアクセスが失敗した場合（ネットワークエラー、パース失敗など）:**
  システムはエラーログを記録し、その Source の処理をスキップして次の Source の処理へ進む。
- **3-2a. 取得したコンテンツがすべて登録済みだった場合:**
  新規 Finding の保存は行わず、各コンテンツについてステップ 3-6 の更新判定のみ行う。その後 Source の `lastFetchedAt` を更新して終了する。
- **3-4a. コンテンツ本文の取得・本文化に失敗した場合:**
  Markdown 本文として「取得に失敗した旨」「判明しているメタ情報（タイトル・URL・抜粋など）」のみを記載して保存する。フロントマターのみのファイルは生成しない。
- **3-6a. 情報源が `contentUpdatedAt` を提供しない場合:**
  更新判定をスキップし、既存 Finding はそのまま保持する。
- **3-1b. 1ページ目で取得したコンテンツが全て未登録だった場合（新しい Source または長期未取得）:**
  さらに古いコンテンツが存在する可能性があるため、2ページ目（次ページ・追加エントリ）を取得して同様の処理（重複チェック → 未登録分 INSERT）を行う。ただし2ページ目以降は繰り返さない（無限ループ防止）。
